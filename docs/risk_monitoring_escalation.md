## 1. 风险管理框架

```
┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ 风险识别 │ →  │ 风险评估 │ →  │ 风险应对 │ →  │ 风险监控 │ →  │ 风险关闭 │
└──────────┘    └──────────┘    └──────────┘    └──────────┘    └──────────┘
```

| 类别 | 代码 | 说明 | 示例 |

## 2. 风险评估标准

### 2.1 概率评估

| 等级 | 概率范围 | 描述 | 分值 |
|------|----------|------|------|
| 极高 | 81-100% | 几乎确定会发生 | 5 |
| 高 | 61-80% | 很可能发生 | 4 |
| 中 | 41-60% | 可能发生 | 3 |
| 低 | 21-40% | 不太可能发生 | 2 |
| 极低 | 0-20% | 极少发生 | 1 |

### 2.2 影响评估

| 等级 | 影响描述 | 进度影响 | 成本影响 | 质量影响 | 分值 |
|------|----------|----------|----------|----------|------|
| 极高 | 灾难性 | >1周 | >20% | 系统不可用 | 5 |
| 高 | 严重 | 3-7天 | 10-20% | 主要功能受损 | 4 |
| 中 | 中等 | 1-3天 | 5-10% | 次要功能受损 | 3 |
| 低 | 轻微 | <1天 | <5% | 轻微影响 | 2 |
| 极低 | 可忽略 | 无 | 无 | 无感知 | 1 |

## 3. 风险应对策略

### 3.1 应对策略矩阵

| 风险等级 | 应对策略 | 响应时间 | 审批层级 |
|----------|----------|----------|----------|
| 🔴 高风险 | 规避/转移/减轻 | 立即 | 项目发起人 |
| 🟡 中风险 | 减轻/接受 | 4小时内 | 项目经理 |
| 🟢 低风险 | 接受/监控 | 24小时内 | 任务负责人 |

### 3.2 应对策略说明

| 策略 | 说明 | 适用场景 |
|------|------|----------|
| **规避** | 改变计划消除风险 | 高风险且可避免 |
| **转移** | 将风险转移给第三方 | 如购买保险、外包 |
| **减轻** | 降低风险概率或影响 | 大多数风险 |
| **接受** | 不采取行动，承担后果 | 低风险或不可避免 |

## 4. 风险升级机制

### 4.1 升级触发条件

```
┌─────────────────────────────────────────────────────────────────┐
│                        风险升级触发条件                          │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  L1: 任务负责人层级                                               │
│  ├── 新识别风险                                                   │
│  ├── 风险状态变化                                                 │
│  └── 低风险风险监控                                               │
│                              ↓ 风险等级≥中 或 无法解决            │
│  L2: 项目经理层级                                                 │
│  ├── 中风险风险处理                                               │
│  ├── 资源协调                                                     │
│  └── 跨任务风险                                                   │
│                              ↓ 风险等级≥高 或 超出权限            │
│  L3: 项目发起人层级                                               │
│  ├── 高风险决策                                                   │
│  ├── 重大变更审批                                                 │
│  └── 项目整体调整                                                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 4.2 升级流程

#### 4.2.1 L1 → L2 升级

**触发条件**:
- 风险等级评估为"中"或"高"
- 任务负责人无法独立解决
- 需要跨任务协调资源

**升级方式**:
1. 立即在项目管理群@项目经理
2. 发送风险升级邮件
3. 在每日站会中重点汇报

**升级内容**:
```markdown
【风险升级】L1 → L2
- 风险ID: [ID]
- 风险描述: [描述]
- 当前等级: [等级]
- 已采取措施: [措施]
- 需要支持: [具体支持需求]
- 建议解决方案: [建议]
```

#### 4.2.2 L2 → L3 升级

**触发条件**:
- 风险等级评估为"高"
- 涉及项目整体调整
- 超出项目经理权限
- 需要额外资源投入

**升级方式**:
1. 立即电话/当面汇报项目发起人
2. 发送正式风险升级报告
3. 召集紧急会议

**升级内容**:
```markdown
【紧急风险升级】L2 → L3
- 风险ID: [ID]
- 风险描述: [描述]
- 当前等级: 高风险
- 可能影响: [进度/成本/质量影响]
- 已采取措施: [措施]
- 需要决策: [具体决策事项]
- 建议方案: [A/B方案及建议]
- 时间敏感性: [说明]
```

### 4.3 升级响应时间

| 升级级别 | 响应方式 | 响应时间 | 处理时限 |
|----------|----------|----------|----------|
| L1 → L2 | 消息/邮件 | 30分钟内 | 4小时内 |
| L2 → L3 | 电话/会议 | 15分钟内 | 2小时内 |

## 5. 风险监控机制

### 5.1 监控频率

| 风险等级 | 监控频率 | 监控方式 | 责任人 |
|----------|----------|----------|--------|
| 🔴 高风险 | 每4小时 | 实时跟踪 | 项目经理 |
| 🟡 中风险 | 每日 | 站会汇报 | 任务负责人 |
| 🟢 低风险 | 每周 | 周报审查 | 风险管理员 |

### 5.2 风险审查会议

**会议安排**:
- **频率**: 每周一次（与周例会合并）
- **参与者**: 项目经理、任务负责人、风险管理员
- **议程**:
  1. 新风险识别（10分钟）
  2. 风险状态更新（15分钟）
  3. 应对措施审查（10分钟）
  4. 风险关闭确认（5分钟）

### 5.3 风险预警机制

```python
# 风险预警触发逻辑
class RiskAlert:
    def check_and_alert(self, risk):
        """
        检查风险状态并触发预警
        
        Args:
            risk: 风险对象
        """
        # 高风险立即预警
        if risk.level == "HIGH":
            self.send_immediate_alert(risk)
            self.escalate_to_sponsor(risk)
        
        # 中风险状态变化预警
        elif risk.level == "MEDIUM" and risk.status_changed:
            self.send_alert(risk)
            self.notify_project_manager(risk)
        
        # 风险临近触发条件
        elif risk.is_near_trigger():
            self.send_warning(risk)
```

### 6.2 风险状态定义

| 状态 | 说明 | 转换条件 |
|------|------|----------|
| 已识别 | 风险已记录，待评估 | 完成风险评估后 → 监控中 |
| 监控中 | 风险正在监控，应对措施已制定 | 风险触发后 → 处理中 |
| 处理中 | 风险已触发，正在处理 | 处理完成后 → 已关闭 |
| 已关闭 | 风险已解决或不再相关 | 不可逆向转换 |
| 已升级 | 风险已升级至更高层级 | 处理完成后 → 已关闭 |
